## 2. 具体实施要求

### 2.1 `top_resonance_limit` 对齐 50（`bridge/stock_today_bridge/config.py`）
- 将 `BridgeConfig.top_resonance_limit` 的默认值从 `int(os.getenv("BRIDGE_TOP_RESONANCE_LIMIT", "30"))` 改为 `int(os.getenv("BRIDGE_TOP_RESONANCE_LIMIT", "50"))`，与 `focus_limit=50` 保持一致。

### 2.2 社区高亮复用 `StockMatcher.group` + 单帖字段全量透传（`run_bridge.py` + `push_to_aihot.py`）
1. **消除匹配与高亮的分裂**：
   - 在 `run_bridge.py` 中，`StockMatcher.group(posts, focus_stocks)` 已经按代码、股票名称、黑话别名把社区帖子归组到 `grouped_posts[stock.code]`；
   - 在调用 `build_snapshot` 时（或组装 `posts` 时），将 `grouped_posts` 中已匹配到某只焦点股但 `post.code` 为空的帖子赋予对应的 `code`（或将 `grouped_posts` 直接传给 `build_snapshot`），使得淘股吧、雪球中按股票名/黑话命中的有效帖同样能进入该股的 `highlights`！
2. **补齐单帖序列化字段（`push_to_aihot.py:build_snapshot.highlights`）**：
   - 对每条入选 highlight 的帖子调用 `score_post(p)` 计算单帖情绪；
   - 序列化字典完整输出以下字段（同时兼容 camelCase 与 snake_case 读取）：
     - `id` / `postId`: `p.post_id`
     - `source`: `p.source`
     - `title`: `p.title`
     - `content`: `(p.content or "")[:280]`
     - `url`: `p.url`
     - `author`: `p.author`
     - `publishedAt`: `p.published_at`
     - `commentCount`: `p.comment_count`
     - `likeCount`: `p.like_count`
     - `viewCount`: `p.view_count`
     - `isKol`: `p.is_kol`
     - `qualityTier`: `p.quality_tier`
     - `sentiment`: `post_score["label"]`（`"bull"` | `"bear"` | `"divergence"` | `"neutral"`）
     - `sentimentTerms`: `post_score["terms"]`

### 2.3 情绪打分否定词修正（`bridge/stock_today_bridge/sentiment.py`）
- 在 `score_post(post)` 扫描 `BULL_WEIGHTS` 词条时，检查命中词条前方紧邻的 1~6 个字符（同一分句内，未被标点 `，。！？；,\.!?;` 隔断）是否包含否定前缀：
  - 否定前缀集合：`("无法", "不能", "不会", "难以", "难", "未能", "没能", "不再", "不可能", "别", "莫", "没有", "未", "不看好", "谨防", "小心", "警惕")`；
  - 若正向词（如 `"涨停"`、`"连板"`、`"封板"`、`"龙头"`、`"大肉"`、`"格局"`、`"反包"`、`"晋级"`）被否定前缀修饰（例如 `"我认为周一冰山无法继续涨停，原因如下"`），则**不得计入正向看多分**，改为计入负分（`-weight`）或归入看空/分歧词条；
  - 新增单测专门覆盖：
    - `"下周连续五个一字跌停。"` → `label == "bear"`
    - `"我认为周一冰山无法继续涨停，原因如下"` → `label` 为 `"bear"` 或 `"divergence"`，绝不能为 `"bull"`。

### 2.4 板块同义词归并、事件词剥离与梯队统计修正（`themes_v2.json` + `pipeline_loader.py` + `run_bridge.py`）
1. **同义概念归并（`themes_v2.json` & `ThemeCatalog.normalize_theme`）**：
   - 将同花顺/开盘啦常见同义概念并入 `themes_v2.json` 对应标准板块的 `aliases`（并在 `normalize_theme` 支持忽略括号后缀与大小写归一）：
     - `"共封装光学(CPO)"`、`"共封装光学"`、`"CPO概念"`、`"光通信模块"` → `"光模块/CPO"`
     - `"飞行汽车(eVTOL)"`、`"飞行汽车"`、`"eVTOL"`、`"通用航空"` → `"低空经济/eVTOL"`
     - `"PCB概念"`、`"印制电路板"`、`"覆铜板"` → `"PCB/覆铜板"`
     - `"黄金概念"`、`"贵金属"` → `"黄金/有色"`
     - `"铜缆高速连接"` → `"算力租赁/AIDC"`（或 `"光模块/CPO"`）
   - 修正过度窄化：不要把单字/泛词 `"机器人"` 强行绑死到 `"人形机器人"`（若原词仅为 `"机器人概念"` 可归入 `"人形机器人"`，但需避免泛化误伤）。
2. **非板块“个股事件/产品/股权词”过滤（`pipeline_loader.py`）**：
   - 在 `pipeline_loader.py` 中新增 `is_event_or_company_tag(raw_tag: str) -> bool` 过滤函数：
     - 凡命中事件/公告/财务/特定车型或参股短语（如包含 `"联合调查"`、`"调查"`、`"复牌"`、`"停牌"`、`"重组"`、`"参股"`、`"控股"`、`"收购"`、`"实控人"`、`"增持"`、`"减持"`、`"回购"`、`"扭亏"`、`"预增"`、`"季报"`、`"年报"`、`"分红"`、`"摘帽"`，或特定产品型号如 `"尊界V800"`）的标签：
     - **保留在个股的 `limit_reason` 与 `why_hot` 文本中**（回答“为什么火”），但**不加入 `stock.themes` 板块列表**，防止生成单股“伪板块”。
   - **焦点股 100% 板块归属兜底**：
     - 过滤事件词后，若某只焦点股的 `themes` 为空，依次尝试从其 `industry`、`rank_reason` 中的行业关键词、`ThemeCatalog.infer_themes(name + " " + why_hot)` 提取标准板块；若仍为空，则归入 `"其他热点"`，确保 50 只焦点股在板块视角下 `unassigned_stock_count == 0`。
3. **板块涨停数去重与领涨股口径修正（`run_bridge.py:build_theme_ladders`）**：
   - **`limitUpCount` 去重**：统计 `legacy_reason_stats` 时，对映射到同一标准板块的多个同义子标签取**最大值 `max()`**（而不是简单相加 `sum()` 导致同一批股票被重复计算），再与桶内实际涨停股数 `sealed_in_bucket` 取 `max(max_stat_count, sealed_in_bucket)`；
   - **`leaderStock` 选股口径**：
     - 若板块内存在 `change_pct > 0` 的股票，优先按 `(change_pct, board_count, resonance_score)` 从高到低选出真正的**领涨股**；
     - 仅当板块内所有股票 `change_pct <= 0` 时，才按 `(resonance_score, change_pct)` 选出代表股；
   - **`ladderSummary` 格式**：生成精炼的板块内部结构摘要（如 `"最高4板(冰山冷热)，首板3家"` 或 `"领涨 莱美药业 +19.93%"`），不重复拼接板块热股数与涨停数。

### 2.5 前端契约全字段无损映射（`modules/short-term-radar/shared/contracts.ts`）
- 在 `mapSnapshot` 中，将 `themeLadders[].stocks` 里的每一只股票也通过 `mapStock()` 完整映射；
- 回填不在 `topResonance` 里的梯队股票到 `stockMap` 时，直接使用 `mapStock(s)` 的完整结果，保留其真实的 `changePct`、`amountYi`、`turnoverRate`、`hotRankThs`、`hotRankDc`、`nicknames`、`sentiment`、`highlights` 等所有字段，彻底修复第 31~50 名股票详情字段归零的 Bug；
- 在 `mapHighlight` 中支持读取 `item.sentiment ?? item.sentimentLabel`、`item.publishedAt ?? item.published_at`、`item.content`、`item.likeCount ?? item.like_count`、`item.viewCount ?? item.view_count`、`item.sentimentTerms ?? item.sentiment_terms`。
