## 一、 本阶段目标（只解决真实数据“取得到、对得齐、讲得清为什么火”）

为第一版极简页面的**两个视角**（1. 热门板块 → 板块内热门股 → 个股详情；2. 热门股 Top 50 → 个股详情）提供**100% 真实、不落空**的数据快照（`.data/short-term-radar-snapshot.json`）：

1. **热门板块数据真实化**：不再只靠静态词典硬凑，而是直接融合 `YM-data-pipeline` 的：
   - `query("legacy_hot_rank")` 返回的 `reason_stats`（同花顺当日涨停原因板块统计，如 `{"低空经济": 11, "飞行汽车": 5}`）与每只热股的 `reason`（如 `"卫星通信芯片+低空经济+卫星应用"`，按 `+` 拆分即为真实题材标签）；
   - `query("market_intraday_state")` 返回的 `limit_up`（涨停池，含 `board` 连板数、`pct` 涨跌幅、`industry` 所属行业、`seal_time` 封板时间）；
   - `docs/aihot_research/dict/themes_v2.json`（Grok 第六波核验的 60 大高频题材与别名映射）。
2. **热门股 Top 50 与「为什么火 (`whyHot`)」字段打通**：
   - 先从 `market_intraday_state`（或 `legacy_hot_rank`）获取最近实际交易日 `trade_date`（格式 `YYYYMMDD`，如 `"20261016"`），再调用 `query("market_hot_rank", source="ths", trade_date=trade_date, limit=50)`，即可稳定拿到同花顺热榜 Top 50 及核心字段 **`rank_reason`（完整的「行业原因 + 公司原因」文本）** 和 **`concept`（JSON 字符串数组，如 `'["冰雪产业", "体育产业"]'`）**；
   - 同时结合 `query("market_hot_rank", source="dc", limit=50)`（东财人气榜 Top 50，字段名为 `ts_code`、`ts_name`、`rank`、`pct_change`）；
   - 为每只股票合成清晰的 **`limitReason`**（简短标签串，如 `"卫星通信芯片+低空经济"` 或概念组合）与 **`whyHot`**（详细原因正文，优先取同花顺 `rank_reason`，其次取涨停原因 `reason` + 连板/封板描述），让前端点开股票就能直接看到“它为什么火、具体是什么情况”。

## 二、 允许修改的文件边界

1. `bridge/config.py`：将 `research["themes"]` 指向 `docs/aihot_research/dict/themes_v2.json`；
2. `bridge/schema.py`：在 `FocusStock` 及 `to_dict()` 中补充 `limit_reason: str = ""`（`limitReason`）、`why_hot: str = ""`（`whyHot`）、`seal_time: str = ""`（`sealTime`）；
3. `bridge/pipeline_loader.py`：
   - `ThemeCatalog.load()` 支持索引 `themes_v2.json` 的 `aliases`（板块别名 → 标准题材名映射），当拆解 `legacy_hot_rank.reason` 或 `ths_hot.concept` 时，若命中别名可归一到标准题材名，未命中则直接保留原始概念名作为独立板块（绝不丢进“未归题材”）；
   - `parse_hot_rank()` 兼容 `ths` 与 `dc` 真实返回字段：`ts_code`（Added in ` _first(row, "code", "stock_code", "symbol", "secu_code", "ts_code")`）、`ts_name`、`pct_change`，并提取 `concept`（解析 JSON 数组或列表）与 `rank_reason`；
   - `load_pipeline()`：
     1. 先调 `market_intraday_state` 拿到 `trade_date`（如 `"20261016"`）；
     2. 调 `market_hot_rank(source="ths", limit=100)` 时若帶 `trade_date` 参数（或无参返回空时用 `trade_date` 重试一次）拿到完整同花顺热榜与 `rank_reason`；
     3. 新增调用 `legacy_hot_rank`（即同花顺热点+涨停原因归因），保存其 `items`（含 `code`、`name`、`zhangfu`、`reason`、`chengjiaoe`）和 `reason_stats`；
   - `build_focus_pool()`：
     1. 涨停池行读取兼容真实字段：`board`（连板数）、`pct`（涨跌幅）、`industry`（所属行业）、`seal_time`（封板时间）；
     2. 整合 `ths_hot`、`dc_hot`、`legacy_hot_rank`、`intraday.limit_up`：每只股的 `themes` 合并词典命中题材 + `legacy_hot_rank.reason` 拆分题材 + `ths_hot.concept` 概念，若仍为空则用 `industry` 兜底；
     3. 填充 `limit_reason`（一句话标签原因）与 `why_hot`（详细原因）；
4. `bridge/run_bridge.py`：在组装 `theme_ladders`（热门板块列表）时，按板块内上榜热股数/涨停数及热度排序，确保每个热门板块下包含完整的板块内热门股列表及 `whyHot`；
5. `bridge/tests/fixtures/pipeline_sample.json` 与 `bridge/tests/test_*.py`：补充真实字段形状（`ts_code`、`board`、`pct`、`rank_reason`、`legacy_hot_rank`）的离线单测；
6. `modules/short-term-radar/contracts.ts`：将快照里的 `limitReason`、`whyHot`、`sealTime` 透传映射给前端 `RadarStockItem`。
